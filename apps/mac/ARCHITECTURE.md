# Peek.app architecture

This is the map for everyone working under `apps/mac`. The binding design is
`.ref/notes/BLUEPRINT.md` (§1.6 IPC, §1.7 state, §1.8 start-up, §8 macOS app) plus
`understanding/visual.md` as amended by BLUEPRINT §0.1. This file records how that design is
split into modules, who owns what, and the exact interfaces between the parts.

## 1. Layout

```

  Sources/App/                    the ONLY code in the app target
```

## 2. Modules and ownership

|---|---|---|---|

| **PeekIPC** | foundation | `DaemonLink` (the `DaemonLinking` implementation), `DaemonSocket`, the POSIX socket | PeekCore |
| **CQuickJS** | drawing agent (from now on) | vendored quickjs-ng + `peek_qjs.c` / `include/peek_qjs.h` | — |
| **PeekDrawing** | **drawing agent** | `DrawingRuntime: DrawingRuntimeProviding`, per-Silicon `DrawingHosting` (JSRuntime thread, prelude, recorder, frame scheduler, compositor, CG replay, glass layers, validator, fallback visual) | PeekCore, CQuickJS, AppKit, SwiftUI, QuartzCore, CoreText |
| **PeekAudio** | **audio-input agent** | `SpeechPlayer: SpeechPlaying`, `MicRecorder: MicRecording` | PeekCore, AVFoundation, Accelerate |
| **PeekInput** | **audio-input agent** | `InputHub: InputHubbing` (+ per-bubble `DrawingInputSource`), `BackdropSampler: BackdropSampling`, `ImageCache: ImageProviding`, appearance, pointer | PeekCore, AppKit, ScreenCaptureKit, ImageIO |
| **PeekUI** — Slots (incl. HotKeys), Chrome, coordinator | **ui-slots agent** | `PeekCoordinator` (event routing, `PeekPresenting`), `SlotManager`, `SlotPanel` (+ `_hasActiveAppearance`), slot state machine, `Slots/HotKeys.swift` (Carbon; also the app-wide bare-Esc hot key of the Esc router, `Slots/EscapeRouting.swift`), chrome (arc, pills, question arc, curved text field, ask controls, mic/keyboard, waveform, down-arrow, TEST badge, hover tooltip and tap-to-expand popup) | all PeekKit modules, SwiftUI, AppKit, Carbon |
| **PeekUI** — Settings, Simulation, MenuBar | **ui-settings agent** | `MenuBarContentView`, `MenuBarLabel`, `SettingsRootView`, Simulation, testing-environments view, settings persistence through `PeekCoordinator.setSetting` | as above |
| **App target** (`Sources/App`) | foundation | scenes, delegate, service registration, update hooks | PeekUI, PeekCore, PeekIPC, ServiceManagement |

Rules:

- **PeekCore is frozen.** Other agents code against it and never edit it. If something is missing, ask for it
  (the foundation agent's `requests`) instead of redefining a type elsewhere. Additive changes are made by the
  foundation owner only.
- Each module edits only its own directory under `Packages/PeekKit/Sources/<Module>` and
  `Packages/PeekKit/Tests/<Module>Tests`. PeekUI is shared by two agents: ui-slots owns
  `Sources/PeekUI/{Coordinator,Slots,Chrome}/` (hotkeys live in `Slots/HotKeys.swift`, as in BLUEPRINT §8.2; there is
  no `HotKeys/` directory), ui-settings owns `Sources/PeekUI/{Settings,Simulation,MenuBar}/`.
- All the foundation's placeholder files have been replaced by their owners (none is left). The public names the
  rest of the app relies on must keep their signatures:
  - PeekDrawing: `DrawingRuntime` (init(), `DrawingRuntimeProviding`), `FallbackDrawingHost`, `QuickJSInfo.version`.
  - PeekAudio: `SpeechPlayer()` (`SpeechPlaying`), `MicRecorder()` (`MicRecording`).
  - PeekInput: `InputHub(images:speech:mic:backdrop:)` (`InputHubbing`), `BackdropSampler(paths:)` (`BackdropSampling`),
    `ImageCache(paths:)` (`ImageProviding`).
  - PeekUI: `PeekCoordinator` (the init shown in `Coordinator/PeekCoordinator.swift`, `start()`, `stop()`, `link`, `paths`,
    `settingsWarnings`, `dismissAll()`, `PeekPresenting`), `PeekComposition.makeLive(bundle:)`,
    `MenuBarContentView(coordinator:)`, `MenuBarLabel(coordinator:)`, `SettingsRootView(coordinator:)`.
- New initializer parameters on these types must have default values, so `PeekComposition.makeLive` keeps compiling
  without an edit from another owner.
- The app holds **no tokens and no network**. Everything remote goes through peekd.
- Swift 6 language mode everywhere; `ExistentialAny` is on in PeekKit (`any Protocol` spelling).
- Tests never touch the real `~/Library/Application Support/Peek`, `~/.silicon*` or launchd: build `PeekPaths(home:)`
  from a temp dir, run `DaemonLink` against an in-process fake socket server (see `Tests/PeekIPCTests/FakePeekd.swift`),
  and construct `PeekCoordinator(..., persistSettings: false)`.

## 3. Threading

- UI-facing protocols (`DrawingHosting`, `DrawingRuntimeProviding`, `DrawingInputSource`, `InputHubbing`,
  `BackdropSampling`, `ImageProviding`, `SpeechPlaying`, `MicRecording`, `PeekPresenting`) are `@MainActor`:
  frames are built on the main thread (visual.md B4), AppKit and SwiftUI live there.
  Implementations move heavy work to their own threads: one `Thread` with a 4 MiB stack per QuickJS VM, audio
  render threads, image decoding off-main.
- `DaemonLinking` is `Sendable` and implemented by an `actor`. Its event stream delivers events **in arrival order**
  (TTS chunk order matters). Consumers hop to the main actor themselves.
- `peek_vm_*` calls are single-threaded per VM; only `peek_vm_request_abort` may be called from another thread.

## 4. Interfaces (PeekCore/Interfaces.swift)

### 4.1 `DaemonLinking` (PeekIPC implements: `DaemonLink`)

```swift
public protocol DaemonLinking: Sendable {
    func start() async                      // connect + reconnect with backoff, idempotent
    func stop() async                       // close; pending requests fail with .disconnected; streams finish
    func events() async -> AsyncStream<DaemonEvent>          // new subscriber stream, ordered
    func states() async -> AsyncStream<DaemonLinkState>      // starts with the current state
    func send<R: UIRequest>(_ request: R, blobs: [Data], timeout: Duration?) async throws(DaemonLinkError) -> R.Reply
    func setRequestHandler(_ handler: (@Sendable (DaemonRequest) async -> DaemonReply)?) async
}
```

`DaemonLink` details:
- Socket `/var/tmp/silicon-peek-<uid>/peekd.sock`, or `PEEK_DAEMON_SOCKET` (tests only). Before connecting it checks
  that the directory is a real directory owned by us with mode `& 0o077 == 0`, that the socket is a socket owned by
  us, and after connecting that `getpeereid` returns our uid. Paths ≥ 104 bytes are refused.
- First frame: `{"v":1,"id":…,"op":"hello","role":"ui","app_build":1000,"app_version":"0.1.0","protocols":[1]}`
  (build and version from Info.plist). A reply whose `protocol` is not in `[1]` is refused and retried.
- Framing: NDJSON + length-declared blobs (`"bin":[n…]`), strict JSON (duplicate keys rejected), line ≤ 1 MiB,
  blob ≤ 10 MiB, ≤ 40 MiB per frame; `voice.submit` WAV ≤ 4 MiB is checked before sending; `tts.chunk` ≤ 64 KiB is
  checked on receipt. A protocol violation closes the connection and reconnects.
- Requests are correlated by UUID `id`; default timeout 30 s; reconnect backoff 250 ms → 4 s (×2, ±20% jitter).
- Unknown events surface as `.unknown(name:fields:)`; known events that fail to decode as `.malformed(name:reason:)`.
- peekd → UI requests are decoded into `DaemonRequest`; unknown ops and a missing handler are answered `unknown_op`,
  undecodable fields `invalid_request`.
- `DaemonLinkState`: `.idle`, `.connecting(attempt:)`, `.connected(HelloResult)`, `.waiting(retryIn:reason:)`
  (reason is a full sentence, e.g. "peekd is not running: no socket at …"), `.stopped`.

Most replies to UI requests other than `hello` decode as `IPCAck` (any object). Errors are `IPCErrorBody`
(`code`, `message`, `hint`, `retryable`, `details`), identical to the CLI error shape.

Settings › Permissions uses pane-local typed IPC requests: `permissions.contexts` lists saved login
contexts with a home id, immutable context id, actor, organization, API origin and environment;
`permissions.ting` pins that home/context and accepts `start`, `status`, `complete`, `cancel` or `enroll`.
Its response contains public review metadata and an enrollment flag. The app checks the returned
context, actor, organization, review identifiers and callback state, and opens only HTTPS review links
without embedded credentials. Context changes and pane dismissal discard the code and fence late replies.
The daemon owns durable retry receipts and completion codes. An interrupted completion can be retried
without re-entering its code. Changed terms require fresh review. Saving approval never enables deliveries;
the separate **Enable deliveries and retry queued answers** action enrolls only the selected context.
Clearing local review preserves existing enrollment and queued answers; revocation remains in IAM.

There is **no live word or transcript data** anywhere (D9): no `speech.word`, no `word` event, no `mic.transcript`.

peek 0.1.2 also reads `peek.show.expires_at` (every kind), `replaces` and `schedule_id`, and `queued_behind` is the
Silicon's waiting count (the badge's first value).

Additive fields this build sends or reads beyond the §1.6 table (peekd ignores unknown fields):
`voice.submit.context`, `voice.submit.languages` (Locale.preferredLanguages when `stt_language` is `auto`),
`message.context`, `focus.context`, and `slots.state[].environment {id?, name, generation?}` for the TEST pill.
`peek.show.ask_id` is read from the top level, falling back to `ask.ask_id`.

Answer values (`answer.value`, `stt.result.value`, `input.ask.value`) are raw JSON: text → string,
single choice → option id, multiple choice → array of option ids, slider → number, range → `[from, to]`
(`AskValue.jsonValue` / `AskValue(json:for:)`).

### 4.3 Drawing (PeekDrawing implements)

```swift
@MainActor public protocol DrawingRuntimeProviding: AnyObject {
    var glassMode: GlassMode { get }                     // .live when -[NSWindow _hasActiveAppearance] exists (D13)
    func makeHost(for key: SiliconKey, initial: String, images: any ImageProviding) -> any DrawingHosting
    func validate(scriptAt url: URL, options: ValidationOptions) async -> ValidationReport   // peekd's drawing.validate
}

@MainActor public protocol DrawingHosting: AnyObject {
    var key: SiliconKey { get }
    var status: DrawingHostStatus { get }               // .empty/.loading/.ready(sha256)/.fallback(DrawingFailure)
    var input: (any DrawingInputSource)? { get set }
    var onFailure: (@MainActor (DrawingFailure) -> Void)? { get set }   // → drawing.error
    var onLog: (@MainActor (String) -> Void)? { get set }               // peek.log (Simulation)
    func load(_ script: DrawingScript) async throws(DrawingFailure)     // top level runs once, then paused
    func unload()
    func attach(to visualView: NSView)                  // the 100 × 100 unit square view
    func detach()
    func deliver(_ event: DrawingEvent)                 // enter, leave, send, answer, click, move (no `word`)
    func wake()
    func isOverContent(unitPoint: CGPoint) -> Bool      // B9 hit test, for click-through
    func validate(_ script: DrawingScript, options: ValidationOptions) async -> ValidationReport
    func awaitFrame(timeout: Duration) async -> Bool      // peek 0.1.2 pre-warm: the next frame is committed
}
```

- Hosts are keyed by `SiliconKey` (context, org, actor), not by slot: the same VM survives `register side` moves
  (`SlotMove.between(old, new)` derives `move` events from successive `slots.state` tables).
- `DrawingEvent.name` / `.payloadJSON` are exactly what `__peek_event(name, payload)` receives.
- `ValidationReport` is the `drawing.validate` reply (§1.6): `ok`, `stats` (`frames`, `p50_ms`, `p95_ms`,
  `max_ms`, `ops_max`, `glass_rebuilds`), `warnings [{code, message}]`, `logs`, `error {message, stack, frame,
  input_summary}`, `dump`, plus `previewPNG` (sent as the reply blob).

Public PeekDrawing names beyond the protocols:

- `DrawingRuntime()` / `DrawingRuntime(glassMode:)`: the provider; `glassMode` defaults to the `_hasActiveAppearance`
  self-check (Simulation passes the mode it wants to show).
- `DrawingHost`: the real per-Silicon `DrawingHosting` (QuickJS thread, prelude, op-stream decoder, frame scheduler,
  compositor, CG replay, glass/blur/vibrant layer views, B10 failure handling). `FallbackDrawingHost` draws the "?"
  fallback visual when no script is loaded or a drawing failed.
- `DrawingValidator`: the A9 validator behind `drawing.validate` (`--preview` PNG, `--dump-frame` with glass layers
  carrying `path`, `local_path`, `transform` and `hash`; the at-most-10-per-second glass-rebuild warning).
- `DrawingLimits`: the B10 limits (the 4 ms frame budget and how many overruns within 5 s end in the fallback).
- `SampleDrawings`: the embedded, tested sample drawings (`cassette`, `deck`, `eye`, `glassOrb`, `minimalDot`,
  `sliderGauge`, `vinyl`; `all`); `QuickJSInfo.version`.

### 4.4 The QuickJS shim (Packages/CQuickJS/Sources/CQuickJS/include/peek_qjs.h)

Swift sees only `peek_qjs.h`; `quickjs.h` is deliberately outside `include/`. One `PeekVM` per drawing:

```c
PeekVM *peek_vm_new(const PeekVMConfig *);   // memory_limit (16 MiB), max_stack_size (1 MiB), op_capacity, log cb,
                                             // measure cb (PeekMeasureCallback + measure_opaque, for measureText)
PeekStatus peek_vm_eval(vm, src, len, filename, strict, deadline_ns);
PeekStatus peek_vm_bind_entry_points(vm, hide_globals);  // after the prelude: binds __peek_frame/__peek_event
PeekStatus peek_vm_frame(vm, input_json, len, deadline_ns, PeekFrameOutput *out);
PeekStatus peek_vm_event(vm, name, payload_json, len, deadline_ns);
peek_vm_error_message / peek_vm_error_stack / peek_vm_request_abort / peek_vm_clear_abort /
peek_vm_memory_used / peek_vm_run_gc / peek_vm_op_capacity / peek_monotonic_ns / peek_qjs_version / peek_vm_free
```

- Intrinsics: BaseObjects, Eval, RegExp (+compiler), JSON, MapSet, TypedArrays, Promise. No std/os, no Date,
  no timers, no module loader.
- Globals installed before the prelude: `__peek_ops` (a `Float64Array` over native memory, zero-copy),
  `__peek_flush(len, strings, again)`, `__peek_log(message)` and `__peek_measure(font, text)`. `__peek_measure`
  returns the `PEEK_TEXT_METRICS_COUNT` (7) numbers indexed by `PeekTextMetric` (width, actual left/right/ascent/
  descent, font ascent/descent) from the config's `PeekMeasureCallback` (Core Text, in PeekDrawing), all 0 without
  one; the prelude's `ctx.measureText` uses it. The prelude defines `__peek_frame(input)` (required) and
  `__peek_event(name, payload)` (optional); `peek_vm_bind_entry_points(vm, true)` captures them and deletes all six
  globals so a drawing cannot reach them.
- CQuickJS compiles QuickJS with `-O2` even in Debug (at -O0 it is 5–10× slower and misses the 4 ms budget).
- `PeekStatus`: `OK`, `THREW` (message + stack with `file:line:col`), `INTERRUPTED` (deadline passed or abort;
  uncatchable by the script), `OUT_OF_MEMORY` (destroy the VM → fallback visual), `MISSING_ENTRY`,
  `INVALID_ARGUMENT` (e.g. input not JSON). Deadlines are `peek_monotonic_ns()` values (CLOCK_UPTIME_RAW).
- `PeekFrameOutput` (ops, op count, strings as bytes + offsets + lengths, `again`) stays valid until the next call.
- Pending promise jobs run after each call under the same deadline.
- The shim calls `JS_UpdateStackTop` on every entry; run each VM on a thread whose stack exceeds `max_stack_size`
  (the blueprint's 4 MiB thread for the 1 MiB default).

### 4.5 Input (PeekInput implements)


listeners; InputHub uses this, the coordinator chains `onChange`), `effectiveSource` (`.wallpaper` until Screen

`ScreenCoordinates`; `SystemWallpaper`, `WallpaperDecoder`, `WallpaperLayout`; `PaletteExtractor`, `SRGBColor`,

### 4.6 Audio (PeekAudio implements)

```swift
@MainActor public protocol SpeechPlaying: AnyObject {
    func handle(_ event: TTSStreamEvent)                 // begin / chunk / end / failure, forwarded from the link
```

`MicRecordingResult.isSilent` is the −50 dBFS "nothing heard" guard (§1.9.5): silent recordings are never uploaded.

### 4.7 Presentation (PeekUI implements; the App target and Simulation use it)

```swift
@MainActor public protocol PeekPresenting: AnyObject {

    func present(_ show: PeekShowEvent)
    func cancel(sendID: String, reason: PeekCancelReason)
```

Simulation presents `PeekShowEvent`s with `context: .simulation` and feeds bundled PCM to `SpeechPlaying` through

`PeekCoordinator` (the `PeekPresenting` implementation) beyond the foundation surface:

- `init(..., presentation: PresentationMode = .automatic, timing: BubbleTiming = BubbleTiming())`;
  `PeekComposition.makeLive(bundle:)` passes `presentation: .live` (real panels); tests get `HeadlessSlotSurface`.
- `summon(_ slot:)` (hotkeys), `handle(_ event: DaemonEvent)`, `handle(_ request: DaemonRequest) async -> DaemonReply`,
  `host(for:)`, `slotManager` (`phase(of:)`, `onPhaseChanged`), `hotkeyProblems` (listed in Settings › Keyboard),
  `glassMode`, `drawingLog` (Simulation), `usesLivePanels`.
- peekd → UI requests handled: `drawing.validate`, `drawing.load`, `app.update.prepare`, `app.quit`, `app.uninstall`,
  and `ui.status` / `doctor` (both answered with `UIStatusReport`: mic permission, hotkeys registered/failed, glass,
  services; peekd's `doctor` op is `UiDoctor` in silicon-peek-client). The UI also pushes `ui.status` after hello
  and on every change; peekd keeps the latest push per connection and falls back to it when its live `doctor`
  relay fails (`ui_status_source: "pushed"`). A peekd that does not take it answers `unknown_op`, which is tolerated.

The chrome (`Sources/PeekUI/Chrome`) is a pure layout (`ChromeLayout.compute`) drawn by SwiftUI. The user's UI
feedback (`.ref/notes/ui-feedback.md`, binding, overrides the blueprint) is implemented there:

- no background of any kind: every element is its own glass over whatever is on screen (compact mode's
  `stripRect` is only a layout region);
- `ChromeTarget` / `ChromeLayout.target(at:)`: hover is fed from the panel's display-link tick (tracking areas do
  not fire in a never-key panel of a never-active app) into `SlotChromeModel.pointerMoved(to:buttonDown:)`;
  interactive chrome has a rim and a lift shadow at rest, springs up on hover and squashes on press (`ChromeFeel`);
- cut-short text is flagged on `ChromeLayout.Item.truncated` / `Question.truncated` with its full text;
  `ChromeOverlay` builds the hover tooltip and the tap-to-expand popup (bounce in, spring out; Esc through the
  Esc router's transient Carbon hot key, a click outside through the polled mouse button);
- long text is a narrow, tall `TextColumn` that grows away from the screen edge and stays inside the panel;
- sliders follow the pointer continuously and spring onto the nearest step on release, with a dot per step;
- a text ask's field is a curved band (`ChromeLayout.CurvedField`, drawn by `CurvedFieldView` over an invisible
  `TextField`) right next to the question; upright question-over-field blocks on the left/right arcs;
- the pointer over the chrome (or an open popup) pauses a show's auto-dismiss (`BubbleEvent.pointer(inside:)`).

peek 0.1.2 (`.ref/notes/v0.1.2-contract.md` §8, binding with `v0.1.2-agreed.md`):

- **Queue.** peekd holds each Silicon's FIFO queue; Peek.app gets only the current send. A same-Silicon `peek.show`
  never replaces the bubble on screen (`SlotScheduler.decide` → `.enqueue`; only an idle summon makes way). `--replace`
  arrives as `peek.cancel{replaced}` (the bubble leaves, speech stops) and the new `peek.show`, shown right after.
- **"+N" badge** (`ChromeContent.waiting`, `ChromeLayout.Buttons.badge/badgeSize`, `WaitingBadgeView`): starts at
  `peek.show.queued_behind`, follows `queue.state` for that send (`SlotManager.applyQueueState`; remembered for a send
  still waiting for its slot). Static chrome, upright, pill shade, bumps 1.0 → 1.15 → 1.0 on change. Normal mode: at the
  mid-angle between the down-arrow and the keyboard; compact mode: on the down-arrow's top-trailing rim.
- **Pre-warm** (`BubbleMachine.Stage.prewarming`, `BubbleEffect.prewarm`, `SlotSurface.prewarm()`, `PrewarmStrategy`):
  `.begin` orders the panel in at its real frame at 1 % opacity with the content at rest, sends `shown`, delivers
  `enter` and the `send` snapshot; the slide starts once ≥ 0.35 s and ≥ 3 frames passed, the drawing committed a frame
  (`DrawingHosting.awaitFrame`) and a backdrop sample exists (≤ 2 s old with the screen source, or 0.25 s passed), at
  most 0.6 s (`prewarm_timeout` is logged with what was missing). `slideIn()` then jumps the content beyond the edge
  (committed first) and restores full opacity. The off-screen variant is kept for comparison: the window server does
  not run the display link off screen, so it always hits the cap (`scripts/capture-slide-in.sh --prewarm offscreen`).
- **Early backdrop** (`BackdropSampling.warm/sampleAge`): `present` tracks the key at once (before activation);
  `updateTable` keeps every occupied slot warm (wallpaper refresh / every 10 s with the screen source).
- **Esc router** (`EscapeRouting`, `EscapeKeyProviding`, `CarbonEscapeKey`; replaces the popup's own Esc hot key): one
  app-wide Carbon bare-Esc hot key ('PEES'), held only while a bubble is in its 3 s grace from its slide-in start, the
  pointer is over a bubble, an Esc window the Carbon opened is running (0.4 s double-Esc, 2 s hint) or a popup is open,
  and never while a Peek window is key. Target: popup → latest Esc window → hovered → newest bubble. A failed
  registration adds "Esc for peeks is taken by another app; use the down-arrow" to the hotkey problems.
- **Esc semantics** (`BubbleMachine`): show/speak — one Esc slides the visual out and keeps the audio (`esc` after
  0.4 s), a second within 0.4 s also stops it (`esc_double`); ask — one Esc collapses it to the compact ask
  (`AskPresentation.collapsed`: question, `^` and the buttons; controls hidden; still answerable), a second within 0.4 s
  dismisses it (`esc`, speech stops); on a compact ask an Esc shows "Esc again to dismiss" (the row's hint pill,
  fades in/out 0.2 s) and a second within 2 s dismisses it. Esc while typing or recording discards the input. `^`
  (`ChromeTarget.expand`, `ChromeActions.expand`), a click on the question, the hotkey, the keyboard or mic button
  expand it. The down-arrow always dismisses (asks included) and never collapses.

Debug builds read `PEEK_DEBUG_HOVER`, `PEEK_DEBUG_PRESS`, `PEEK_DEBUG_EXPAND` (a target such as `option-1`,
`text-0`, `image-0`, `question`, `mic`, `field`, `expand`), `PEEK_DEBUG_DRAG` (a slider fraction held mid-drag) and
`PEEK_DEBUG_TYPE` (text typed once the bubble is up) to force those states for screenshots (`ChromeDebugHooks`), plus

## 6. Geometry (PeekCore/Geometry.swift)

`SlotGeometry.layout(slot:mode:visibleFrame:) -> SlotLayout`, pure functions of `NSScreen.visibleFrame`.

Coordinate systems: *screen* = AppKit global (y up); *panel-local* = y-down from the panel's top-left (SwiftUI,
flipped views); *units* = the drawing's 100 × 100 square, y-down.

Normal mode, measured from `understanding/peek all-positions.jpg`:
- visual circle Ø = 12% of the screen width, clamped to 88…240 pt; gap to the visible-frame edges 0.45 r;
- information arc: baseline circle of radius 4.5 r whose apex is 1.3 r from the visual centre toward the screen
  centre, spanning ±32°; its endpoints are ≈ 2.45 r from the visual centre (the notes' "2.3–2.6 × r"). The arc is
  not concentric with the circle. Arcs face the screen centre in compass steps (corner arcs are diagonal, as in the
  image), while `SlotLayout.facing` (= `input.slot.facing`) points at the true visible-frame centre (visual.md B8);
- content sits on the outer side of the baseline (toward the screen centre). `placeElements` lays elements out
  flex-centred in reading order (left→right; top→bottom on the left/right slots), each at most
  `maxElementAlongExtent` = (arc length − 2 gaps) / 3, rotated to follow the arc (elements on the vertical left/right
  arcs stay upright and only tilt with the curve). `InfoArc.concentric(offset:)` gives the question arc;
- the panel is sized once for the largest state (an ask with image options, label pills and the question arc),
  extended to the edge(s) it slides out of, clamped to the visible frame, rounded to whole points;
- `hiddenOffset` is the panel-local translation that puts all content beyond the visible-frame edge: animate
  between it and `.zero` (spring in, `.smooth` out). The panel itself never moves or resizes.

Compact mode: a 32…48 pt visual at the left of a straight 280…520 pt line with a content row of 88 pt, anchored at
the slot's edge (right slots are right-aligned, so the row stays on screen); `SlotLayout.line` replaces `arc`.

Helpers: `visualFrameOnScreen`, `drawingUnits(fromScreen:)`, `panelPoint(fromScreen:)`, `screenPoint(fromPanel:)`.

## 7. `InputSnapshot` (PeekCore/InputSnapshot.swift)

visual.md A4 as amended by BLUEPRINT §0.1: `speech {text, level, progress, done}` (no `word`), `mic {level}` (no
`transcript`), `phase` includes `transcribing`, plus `context` (`production|testing|simulation`) and `glass`
(`live|frosted`). `jsonBytes()` is a fixed-order hand-written encoder for `peek_vm_frame` (non-finite numbers become
`null`); `Codable` round-trips the same JSON for tests and Simulation. `ImageHandle` is `{id, width, height}`.
`Backdrop.sample(red:green:blue:source:previousTone:)` implements Rec. 709 luminance and the 0.45/0.55 hysteresis.
